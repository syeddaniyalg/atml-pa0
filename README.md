# ATML PA0

This repository contains my submission for Programming Assignment 0 (PA0) of the Advanced Topics in Machine Learning course at LUMS. The assignment is organized into four tasks, each implemented as a separate Jupyter notebook. Each task studies a different model family (ResNet, ViT, CLIP, VAE) through implementation, ablation, and empirical analysis, rather than through theory alone.

## Task 1: Inner Workings of ResNet-152

This notebook examines ResNet-152 on CIFAR-10 from several angles:

- A baseline is established by fine-tuning only the final classification head of an ImageNet-pretrained ResNet-152.
- The skip connections in the residual blocks are disabled, and the resulting model is trained and compared against the baseline to study how residual connections affect gradient flow, convergence speed, and stability in deep networks.
- Forward hooks are registered on intermediate layers to extract feature maps, which are visualized as heatmaps and further reduced with UMAP to study how class separability changes with network depth.
- Three training regimes are compared on CIFAR-10: head-only fine-tuning, full-backbone fine-tuning, and training from random initialization. Accuracy, training time, and parameter counts are compared across the three to discuss the compute-accuracy trade-off and the transferability of different layers.

## Task 2: Vision Transformers (ViT)

This notebook uses a pretrained `google/vit-base-patch16-224` model on a small subset of the ImageNet validation set:

- Standard image classification inference is run to check whether predictions are reasonable.
- Attention weights from the CLS token are extracted and visualized as patch-attention overlays across all transformer layers, followed by an analysis of how attention behavior changes with depth and how it compares to CNN-based interpretability methods such as Grad-CAM.
- A patch-masking experiment is conducted, comparing random patch masking against structured center masking, to study the model's robustness to missing input regions.
- A separate classification head is fine-tuned on mean-pooled patch tokens instead of the CLS token, and the resulting accuracy is compared against the standard CLS-token approach to study how pooling strategy affects downstream performance.

## Task 3: CLIP

This notebook uses a pretrained CLIP model (ViT-B/32) on the STL-10 dataset:

- Zero-shot classification is performed using several prompt templates of varying complexity, comparing their effect on accuracy.
- Image and text embeddings are extracted and projected with UMAP to visualize and discuss the modality gap between the two encoders.
- An orthogonal Procrustes alignment is fit between the image and text embedding spaces to attempt closing this gap, and classification accuracy before and after alignment is compared to assess whether the modality gap affects downstream performance.

## Task 4: Variational Autoencoders

This notebook implements a convolutional VAE trained on MNIST:

- The encoder, decoder, and reparameterization step are implemented from scratch, along with a training loop that tracks reconstruction and KL-divergence losses separately.
- The learned latent space is visualized using UMAP to check whether digit classes form separable clusters.
- Reconstruction quality is evaluated qualitatively, and new digits are generated by sampling directly from the latent prior.
- Architecture, loss formulation, and results are compared against Doersch's tutorial VAE implementation on MNIST.

## Requirements

The notebooks are written in Python and rely on PyTorch, torchvision, HuggingFace `transformers`, OpenAI CLIP, UMAP, `kagglehub`, and standard scientific Python libraries (NumPy, matplotlib, tqdm, scikit-learn/scipy). A CUDA-capable GPU is recommended, since several experiments involve fine-tuning ResNet-152 and ViT for multiple epochs.

## Usage

Each notebook is self-contained and can be run independently. Running a notebook will download the required dataset into `./data` and, saves model checkpoints and history in `./models`. There are cells after each training block to load the checkpoint if you already have it saved in `./models`. So, there d no need for training and just run the load cell.
